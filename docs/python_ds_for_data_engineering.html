Python data structures used in data engineering — reference guide with code examples

Core — you'll use these every single day

List []

Ordered Mutable Allows duplicates

The workhorse of batch processing. Use whenever you're collecting rows, records, or chunks to process together.

Where you'll see it
  • Collecting rows from an API before writing to BigQuery
  • Storing partition values to iterate over in Spark
  • Building a batch of records for dlt to ingest
# dlt pipeline: collecting records to yield records = [] for page in api.paginate("/weather"): records.extend(page["data"]) # list.extend is O(n) yield records # List comprehension — very common in pipelines station_ids = [r["id"] for r in records if r["active"]]

Dictionary {}

Key-Value O(1) lookup Ordered (3.7+)

The shape of a single record — whether it's a JSON API response, a database row, or a Spark schema definition.

Where you'll see it
  • Every JSON record from an API is a dict
  • dbt source/model config (profiles.yml, dbt_project.yml)
  • Spark schema as a dict when defining StructType dynamically
  • Lookup tables for mapping codes → labels
# A single weather record record = { "station_id": "KE-001", "temp_c": 28.4, "county": "Embu" } # Fast lookup — O(1). No loop needed. county_map = {"KE-001": "Embu", "KE-002": "Nairobi"} county = county_map.get("KE-001", "Unknown")

Set set()

No duplicates O(1) membership Unordered

Your deduplication tool. Fast to ask "have I seen this before?" without scanning a list.

Where you'll see it
  • Tracking already-processed record IDs to avoid re-ingesting
  • Deduplicating station IDs from messy source data
  • Finding records present in source but missing from target (set difference)
# Track what's already been loaded — no list scan needed seen_ids = set() for record in incoming: if record["id"] not in seen_ids: # O(1) seen_ids.add(record["id"]) yield record # Set operations — great for reconciliation source_ids = {r["id"] for r in source_data} target_ids = {r["id"] for r in target_data} missing = source_ids - target_ids # what failed to load?
Pipeline-specific — critical for data engineering

Tuple ()

Immutable Ordered Hashable

Fixed records that shouldn't change. Tuples can be dict keys and set members — lists cannot.

Where you'll see it
  • Composite keys for deduplication: (county, date, station)
  • Returning multiple values from a function cleanly
  • PySpark Row objects behave like tuples
# Composite key as tuple — usable in a set seen = set() for r in records: key = (r["station_id"], r["date"]) # tuple = hashable if key not in seen: seen.add(key) yield r # Multiple return values def parse_record(raw): return raw["id"], raw["value"], raw["ts"] record_id, value, timestamp = parse_record(row)

Deque collections.deque

O(1) both ends Bounded window Thread-safe

A sliding window. Where a list pops from the front in O(n), a deque does it in O(1). Use for rolling averages or bounded queues.

Where you'll see it
  • Rolling 7-day temperature window for anomaly detection
  • Rate-limited API call buffer (add new, drop old)
  • Task queue in a custom pipeline runner
from collections import deque # Sliding 7-day window — maxlen auto-drops oldest window = deque(maxlen=7) for daily_temp in daily_readings: window.append(daily_temp) if len(window) == 7: rolling_avg = sum(window) / 7

DefaultDict collections.defaultdict

Auto-initialise Group-by pattern

A dict that creates a default value for missing keys automatically. Eliminates boilerplate when grouping records.

Where you'll see it
  • Grouping records by county / partition key before bulk insert
  • Counting occurrences without initialising to 0 first
from collections import defaultdict # Group records by county — no KeyError, no if-key-in-dict by_county = defaultdict(list) for record in records: by_county[record["county"]].append(record) # Counts without initialising counts = defaultdict(int) for r in records: counts[r["status"]] += 1
Advanced — shows up in Spark and larger pipelines

Heap heapq

O(log n) insert O(1) min access Priority queue

Always gives you the smallest (or largest) item efficiently. Used when you need top-N records without sorting everything.

Where you'll see it
  • Top-10 highest risk counties by composite score — no full sort
  • Merge-sort logic inside external sort pipelines (Spark uses this internally)
  • Scheduling retry jobs by next-attempt timestamp
import heapq # Top 5 riskiest counties — O(n log k), not O(n log n) top5 = heapq.nlargest(5, records, key=lambda r: r["risk_score"]) # Priority queue for retry logic retry_queue = [] heapq.heappush(retry_queue, (next_retry_ts, record)) ts, next_record = heapq.heappop(retry_queue)

Dataclass @dataclass

Typed record Auto-generated methods Self-documenting

A class that's just a data container. Replaces messy raw dicts when your records have a defined shape — especially in typed pipelines.

Where you'll see it
  • Defining a WeatherRecord schema before dlt ingestion
  • Strongly-typed pipeline configs (database URL, batch size, etc.)
  • Anywhere raw dicts get unwieldy and you want autocomplete
from dataclasses import dataclass @dataclass class WeatherRecord: station_id: str date: str temp_c: float rainfall_mm: float r = WeatherRecord("KE-001", "2024-06-01", 28.4, 3.2) print(r.temp_c) # 28.4 — no dict["temp_c"] typo risk
Quick rule of thumb: use a list for a sequence of rows, a dict for a single row, a set for deduplication, a tuple for a composite key, and a dataclass when your dict starts having 6+ fields.
